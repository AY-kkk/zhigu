## 1. 产品边界与设计选择

### 1.1 用户已明确的必需能力

| ID | 必须交付 | 不能用什么替代 |
|---|---|---|
| S-01 | 沪／深／北交所 A 股、港股股票全目录搜索 | 五只固定股票、只有代码正则、搜索失败伪装为不存在 |
| S-02 | K 线、成交量、价格与数据状态，接真实行情源 | 静态截图、随机数据、fixture 冒充真实行情 |
| S-03 | 内置丰富指标，至少含 KDJ、MACD；参数可改、多窗格联动 | 只有指标名字、只有模型解释、无实际计算 |
| S-04 | 右侧自然语言策略栏，生成规则并可继续修改 | 通用聊天回复、不可执行的策略文章 |
| S-05 | 历史模拟回测，真实计算交易与资金变化 | 模型编收益曲线、固定胜率、仅标记历史买卖点 |
| S-06 | 策略保存、版本、回测历史、明细与复现 | 刷新即丢失的临时聊天结果 |

### 1.2 本稿采用的设计默认值

以下是为推进开发设计而选择的默认值，可随用户反馈升版，不写成已确认的业务事实。

- 主工作区为 K 线与指标，右侧为策略助手，下方为回测结果；移动端右栏改抽屉／独立页签。
- 历史行情与回测底座先保证日线，提供由日线聚合的周／月 K。**盘中报价、分钟 K、交易所级实时行情的时效和预算尚未确认**，见 §3.1；不得把日线底座宣称为实时终端。
- 一次策略运行针对一个用户选定的股票，覆盖目录内任意合格标的；先做多头、无杠杆的现金账户。多标的组合、做空、杠杆需要独立账户及成交契约，不由模型偷偷加入。
- 策略表达采用受限的结构化 DSL；生成和回测由用户主动操作。修改规则后可再次回测，运行中的旧版本保持不变。
- 模拟回测指选定历史区间的计算任务；不等于实时模拟盘、持续预警或券商实盘委托。本版不要求真实下单。
- 初始资金默认 `100000`，币种随交易柜台；仓位、交易费用、滑点和回测日期在执行前显示。未知费用不能自动填 0。
- 同花顺／东方财富是交互参照，本文不承诺指标初始化、行情速度、复权或回测结果与其逐项相同。

### 1.3 方案比较与本稿选择

| 方案 | 优点 | 主要代价 | 本稿选择 |
|---|---|---|---|
| 行情图表＋受限 DSL＋确定性回测 | 能解释、可修改、可复现，模型不执行任意代码 | 需要指标目录、规则编译与撮合账本 | 采用 |
| 模型生成任意 Python 并执行 | 表达自由 | 需隔离沙箱、依赖治理、资源限制与额外安全验收 | 不作为首个闭环 |
| 嵌第三方完整行情／策略终端 | 页面接入较快 | 数据和策略上下文难统一，能力受服务条款与 API 限制 | 不作为核心交付 |

### 1.4 端到端用户案例

用户搜索「腾讯／00700／0700.HK」，选择腾讯控股 HKD 柜台，看到 K 线、成交量，添加 MACD 和 KDJ。右侧输入：

> 用腾讯做日线策略：MACD 金叉且 KDJ 的 K 小于 30 时半仓买入，MACD 死叉卖出；收盘亏损达到 5% 也卖出。用 10 万港币回测 2022 年至 2025 年。

系统生成可编辑规则卡：标的、指标参数、入场／退出条件、半仓、收盘止损、次一可交易日开盘模拟执行、费用和数据区间。未指定的 MACD／KDJ 参数采用显式默认值。用户点击「运行回测」，完成后查看净值、回撤、基准、每笔成交、未成交原因和假设；把 K 阈值改为 20，生成新版本并比较两次结果。

若历史、复权、交易规则或公司行动数据不足，页面仍可查看已有行情，但该次回测明确返回不足原因，不生成看似完整的绩效。

## 2. 页面与交互契约（S-02／S-03／S-04／S-06）

工作台沿用 `/app/strategies`；新增策略市场 `/app/strategies/market` 与详情 `/app/strategies/market/:strategyId`，作为「交易策略」内部二级入口，共用现有账户和登录守卫，不新增一级导航。市场与工作台可相互切换，保留编辑草稿及返回列表的筛选状态。

```text
┌ 搜索股票／自选切换 ─ 名称 代码 市场 币种 ─ 数据日期与状态 ┐
│ 日/周/月  复权  日期区间  指标管理       │ 策略助手       │
│                                       │ 一句话描述     │
│ K 线 + MA/EMA/BOLL + 十字光标           │ 生成/修改规则  │
│ 成交量                                │ 参数与假设卡   │
│ MACD / KDJ / RSI … 可配置副图           │ 回测配置       │
│                                       │ 保存/运行/取消 │
├ 回测结果：概览 / 净值回撤 / 成交 / 信号 / 运行说明 ─────┤
│ 策略版本、数据快照、费用与结果历史                       │
└───────────────────────────────────────────────────────┘
```

- 桌面侧栏默认宽 360px，可折叠；宽度不足 1100px 时改抽屉；手机以「行情／策略／结果」页签切换，不能横向挤坏图表。
- 搜索支持代码、中文／英文名称、拼音首字母、历史简称。300ms debounce，支持键盘选择、分页，精确代码优先。未带交易所且有歧义时列出候选，不替用户猜。
- 结果展示名称、代码、交易所、证券类型、柜台币种、上市／停牌状态及行情可用性。搜索无结果、目录更新失败、行情失败是不同状态。
- K 线支持拖动、缩放、向前加载、十字光标、多窗格时间同步、恢复默认视图。右侧栏展开不截断图表；ResizeObserver 驱动尺寸变化，卸载释放图表与监听器。
- 必须有可复制的日期、OHLC、成交量和指标数值面板；不能仅用 canvas 表达数字。涨跌红绿同时配文字／符号。
- 价格精度按证券／复权数据的显示规则配置，不能全市场固定两位小数；绘图才转 number，API 与计算保留十进制语义。
- 切换股票、周期、复权或日期时取消旧请求或校验请求序号；旧响应不得画到新标的。加载／错误时明确清除旧标题绑定的数据，不能把茅台价格显示成腾讯。
- 数据不足、停牌、上游异常、指标预热不足、策略不可执行、回测取消均有独立状态；不得用空白图或转圈永久代替。
- 图表指标配置与策略计算配置分别保存。用户改变图表指标，不静默改变已保存策略；提供「将策略指标显示到图表」。
- 生成后的规则卡展示入场、退出、仓位、止损方式、周期与默认假设；高级视图可查看 DSL。业务界面不强迫用户理解内部队列、网关或 Schema。
- 提供「配置买卖规则」窗口：桌面宽抽屉、手机全屏编辑；买入／卖出分别配置指标输出、比较操作、阈值／字段、连续天数及 all／any 条件组，支持高级取反。连续放量有快捷条件与完整解释，见 PRD §3.4～3.5。AI 生成的同一规则树须可回显、编辑并无损保存，不能只返回文字或 JSON。
- 窗口使用带 base_revision 的编辑副本；应用后同步策略卡与 AI 上下文，取消不改草稿，关闭未应用窗口提示保留或放弃。切换买卖页签保留编辑内容；遇到 AI 或其他编辑造成的版本变化时显示冲突与差异，不静默覆盖。保存规则不自动运行回测。
- 策略买卖信号与模拟成交点用不同标记。所有模拟订单、资金和收益明确标识「历史模拟」，不伪装真实持仓。
- 保持现有编辑式品牌、登录守卫和组件体系；不把本需求变成其他页面换肤任务。

图库继续采用 `lightweight-charts` v5，并锁定实际 minor／patch。它负责渲染，不承担指标或回测计算；不因采用该库就宣称内置了 KDJ／MACD。保留其要求的 attribution／NOTICE，见 §15。

## 3. 数据接入、全市场目录与行情契约（S-01／S-02／S-07）

### 3.1 时效能力与当前未决项

| 层级 | 含义 | 本稿状态 |
|---|---|---|
| 历史日线底座 | 已完成交易日 OHLCV、周月聚合、历史回测 | 必做 |
| 盘中延迟行情 | 盘中价格／分钟 K，明确源延迟与时间戳 | 待用户确认目标时效后冻结 |
| 交易所级实时 | 相应实时权限、订阅分发与连接恢复 | 尚未选择供应商／预算，不声称已包含 |

未决项只阻断相应行情层级的实现与签收，不阻断全目录、指标、策略 DSL 和日线回测开发。设计应保存 `observed_at / market_time / delay_seconds? / is_final`，为后续分钟 K 留出接口扩展点；未知延迟展示「时效未验证」，不能展示为实时。

### 3.2 证券目录是独立产品数据

- A 股范围包括上交所主板／科创板、深交所主板／创业板、北交所。港股包括主板／GEM 上市股票及股票类存托凭证，保留多个交易柜台。
- 「全目录」以当日权威上市名单为基准，包括暂停交易的上市股票；新上市、改名、代码变更、退市均有更新链路。ETF、基金、权证、牛熊证、期货不冒充股票，可返回明确类型与不支持原因。
- 已纳入目录的退市证券保留历史身份。上线前历史已退市目录若不完整，必须说明其区间，不宣称具备无幸存者偏差的历史全市场选股能力。
- `security_id` 为稳定实体 ID，`instrument_id` 为交易柜台 ID；A 股外部格式 `600519.SH / 300750.SZ / <实际代码>.BJ`，港股格式 `00700.HK`。代码重用／换码通过带有效日期的 alias 映射，不覆盖历史身份。
- 正则只校验语法。市场、板块、类型、币种、每手股数、最小变动价位、交易日历均从版本化主数据读取；不能只凭后缀决定币种或凭代码位数判断股票。
- 港股输入 `700 / 0700 / 00700` 在市场上下文明确时规范化；人民币柜台保留其真实币种和独立代码，不标为 HKD。
- 名称、代码、拼音／英文 alias 建索引；查询只访问本地目录，不为每个搜索词扫描上游全市场。
- 每个市场交易日前至少刷新一次目录，支持管理员手动刷新；同步采用 staging＋完整性检查＋原子发布。分页失败不把缺失证券批量标记为退市。
- 目录响应带 `catalog_version / catalog_as_of / freshness_status`。目录过期仍可搜索旧快照，但必须显示状态并记录刷新故障。

最少字段：`security_id, instrument_id, exchange, board, asset_type, name, aliases[], currency, calendar_id, listing_date, delisting_date?, trading_status, lot_rule_id, tick_rule_id, valid_from, valid_to?, catalog_version`。

### 3.3 数据源策略：以覆盖实测决定能力

| 数据 | 候选路径 | 冻结要求 |
|---|---|---|
| 沪深北目录 | 交易所名单＋供应商证券主数据／公开接口 | 按市场集合核对，证明北交所代码映射和新股更新 |
| 港股目录 | HKEX 证券／柜台资料＋供应商目录 | 区分证券类型、币种、柜台、暂停上市状态 |
| A 股日 K | 东财历史 K 等候选；正式供应商 adapter 可替换 | 沪深北分别实测，不照搬 SH/SZ 的 secid 规则给 BJ |
| 港股日 K | 新浪历史 K 等候选；正式供应商 adapter 可替换 | 历史深度、成交量、解码、复权因子、断连与限流验证 |
| 公司行动／交易约束 | 可验证的供应商或交易所资料 | 拆并股、分红、停复牌、历史规则有效期；缺项进入回测门禁 |
| 盘中／分钟 | 根据 §3.1 的最终选择冻结 | 时效、历史长度、权限、容量均需另测 |

东财／新浪是待验证候选，不继续沿用「不得更换主路径」约束。免费可访问并不证明全市场、长期稳定或允许面客分发；source-contract 记录展示／存储／用途能力，私有测试与面客使用分开签收。不自动采购或申请新服务。

Adapter 至少区分 `list_instruments / get_bars / get_adjustments / get_corporate_actions / get_trading_status`。源不支持某项时显式返回 capability=false，不伪造完整对象。目录适配、行情适配与回测能力可以来自不同源，但合并须冻结映射与验证证据。

源契约记录：确切 host／URL 或 SDK 版本、参数、字段路径、单位、时区、价格精度、报价范围、交易时段口径、复权方法、分页、频率限制、超时、历史覆盖、解码算法版本、权限用途和验证日期。不能以 AKShare 函数名代替真实网络契约。

新浪港股参考实现涉及压缩行情解码，前复权还需独立因子请求；允许一个有界抓取任务包含多次 HTTP。冻结每类调用上限和总 deadline，取消 S-1.0 的「一次 HTTP」限制。不得执行上游返回的任意脚本／eval；使用固定审核过的解码器。

### 3.4 目录覆盖与行情覆盖分开验收

- `catalog_coverage = 本地与基准名单匹配的有效柜台数 / 基准股票柜台数`，记录日期和分母，不能写死股票总数。
- 全目录签收要求沪、深、北、港逐市场匹配 100%；差异逐项归因并修复，不以抽样五只替代。
- 行情按每个柜台记录 `supported_periods, earliest_date, latest_complete_date, status, reason`。所有目录标的均须能进入页面；无法取数也不能从搜索中隐藏。
- 全市场接入验收要运行有速率限制的覆盖审计，逐项区分正常、停牌、新上市历史短、退市历史、供应商不覆盖、临时故障；供应商不覆盖和临时故障不能算作成功覆盖。
- 历史可用性不等于回测可用性；回测还需公司行动、交易规则、完整日历和费用。UI 展示具体不足，不以“有 K 线”自动启用任意历史回测。

### 3.5 OHLCV 语义

| 项 | 契约 |
|---|---|
| 周期 | `1d / 1w / 1mo`；周月由同一版本日线聚合，日期取该聚合段最后实际交易日 |
| 价格展示 | `raw / qfq / hfq`；每种 capability 独立验证，缺因子禁用对应选项并解释，不冒充复权 |
| 计算原始数据 | 原始 OHLCV、公司行动与因子分开保存；不以展示前复权价模拟实际成交 |
| 数值 | API 价格／金额／指标为十进制字符串，volume 为整数字符串，统一到股；转换规则按源／证券类型冻结，不默认港股一手等于 100 股 |
| 日期 | 日线 `time=YYYY-MM-DD`，按交易所日期；时间戳 RFC3339 UTC；周期额外含 `period_start / period_end / is_final` |
| 窗口 | `start/end` 包含边界；仅 start 时 end 为最新完整日，仅 end 时取截至该日最近 limit 根；都不传取最近 250 根 |
| 分页 | `limit` 默认 250、范围 1～2000；向历史分页采用固定 snapshot 的不透明 cursor；返回 `has_more / next_cursor`，禁止静默截断 |
| 历史深度 | 不沿用 5 年硬上限；可查到源已验证的 earliest_date，长区间通过分页／后台准备，不占住单个 HTTP 请求 |
| 排序 | 日期严格升序、每柜台／周期／快照内唯一，禁止 OHLCV 相同就按值去重不同日期 |
| 缺失 | 空合法窗口返回 bars=[] 与原因；停牌不编造可成交 bar；不明缺口标 incomplete，不能用前收盘补假 K 线 |
| 校验 | 数字有限、量非负、high≥low；OHLC 时段范围以源契约核定。high/low 不含开收竞价时须标 session_scope，不能直接当完整日内区间使用 |
| 完整性 | 日历＋时段结束＋上游完成状态／冻结等待时间共同判断；不能把“返回了当日记录”当已收盘 |

默认历史页面只使用已完成日线；周／月可选显示形成中的聚合 K，但必须标 `is_final=false`，策略不能读取其最终值。港股正常日／半日市分别按日历处理；中国内地与港股节假日不可共用一个工作日表。

### 3.6 快照、缓存和刷新

- 分开记录 `source_contract_version / catalog_version / data_snapshot_id / adjustment_version / calendar_version`。源切换、因子变化和历史修订均可生成新快照，不能只在切源时变版本。
- `finance_market_bars` 按 `instrument_id, period, trade_date, data_snapshot_id` 唯一；已发布快照不可变。最新查询用可更新的快照指针，回测锁定已发布快照。
- 缓存命中必须满足窗口覆盖、最新预期完整日、因子一致性与 freshness；“已有 250 根”不是命中充分条件。
- 收盘后增量更新，历史修订重新构建受影响快照；复权因子更新原子发布对应完整调整视图，不把新旧复权基准拼在一条曲线里。
- 区分自然休市、已知停牌、尚未上市与异常缺口；空窗口采用短 TTL 负缓存，不能永远缓存新股无数据。
- 同一 instrument／窗口／版本未命中采用 singleflight；全局 provider 限流、有限重试＋退避、熔断，不能只限制单用户而放任全市场任务冲垮上游。
- 设计初值：行情读 60 次／用户／分钟，出站并发每 provider ≤2；单 HTTP 8 秒，交互准备总计 20 秒；超出转异步数据任务。最终频率不得超过已冻结源限制。
- 旧快照可用于只读图表，须显示最后数据日与 stale 状态；回测只能使用覆盖已验证且冻结的快照。禁止无提示换源或把未知 freshness 当最新。
- 原始响应及规范化 hash 在允许存储的范围内保留，支持复核；不写入研究证据表，不进入普通日志。原始记录可存私有对象文件，DB 保存 hash／路径／血缘。

## 4. 指标计算契约（S-03／S-08）

### 4.1 首批必做指标

| 类别 | 指标及默认参数 | 用途 |
|---|---|---|
| 主图 | MA：5/10/20/60；EMA：12/26；BOLL：20,2 | 均线／趋势／波动带 |
| 副图 | VOL：量与 MA5/10；MACD：12,26,9；KDJ：9,3,3 | 量价／趋势／摆动 |
| 副图 | RSI：6/12/24；WR：10/6；BIAS：6/12/24 | 强弱与乖离 |
| 副图 | CCI：14；ATR：14；OBV | 通道／波幅／能量 |

每个指标必须有实际计算、参数校验、默认值、输入依赖、预热长度、输出字段和黄金测试。后续扩展通过版本化 registry，不用“支持任意指标”替代清单。SAR、DMI 等扩展不算本批必需项。

### 4.2 一致性规则

- 图表、策略预览和回测使用同一服务端指标核心／同版本 registry。前端只负责渲染结果，避免 TS 与后端各写一套不同口径。
- 指标输入绑定证券、周期、价格基准、快照、参数和 `indicator_engine_version`；缓存 key 包含上述全部维度。
- 内部十进制计算精度 34 位、舍入 HALF_EVEN，展示舍入不参与条件比较；指数平滑逐步舍入的规则同样冻结。API 输出 decimal string 或 null，不输出 NaN／Infinity。
- C=close，H=high，L=low；SMA 为最近 N 个有效 bar 的简单均值；EMA 系数 2/(N+1)，首个有效输入为种子，未达声明预热长度不参与策略。
- MA=SMA(C,N)；EMA=EMA(C,N)；BOLL 中轨 SMA(C,N)，总体标准差（分母 N），上下轨 ±k×标准差。
- MACD：DIF=EMA(C,fast)-EMA(C,slow)，DEA=EMA(DIF,signal)，柱=2×(DIF-DEA)；默认预热 slow+signal-1 根。不得切换成未乘 2 的柱而不升版。
- KDJ：RSV=100×(C-LLV(L,N))/(HHV(H,N)-LLV(L,N))；首个完整 N 窗口以 K前=D前=50 开始，K=(m1-1)/m1×K前+RSV/m1，D=(m2-1)/m2×D前+K/m2，J=3K-2D。窗口最高等于最低时 RSV=50；J 不裁到 0～100。
- RSI：N 个价格变化的上涨／下跌幅均值初始化，之后 Wilder 平滑；平均跌幅为 0 且上涨非 0 时为 100，两者均 0 时为 50。
- WR：100×(HHV-C)/(HHV-LLV)，范围 0～100，平价窗口为 50；不用 -100～0 口径冒充一致。
- BIAS：100×(C-SMA)/SMA，分母为 0 返回 null；CCI：TP=(H+L+C)/3，(TP-SMA(TP,N))/(0.015×平均绝对偏差)，平价偏差为 0 时返回 0。
- ATR：TR=max(H-L,abs(H-C前),abs(L-C前))，首根取 H-L；前 N 个 TR 均值种子，随后 Wilder 平滑。
- OBV：首根为 0，收盘上涨加 volume，下跌减 volume，不变保持；VOL 均量使用实际成交股数。
- MA/EMA/BOLL/WR/BIAS/CCI/ATR 至少 N 根；RSI 至少 N+1 根；OBV 至少 2 根；组合条件取最大预热，再覆盖最大 lag 和交叉判定所需的前一根。图表可显示未成熟序列但标记，策略只使用 ready=true 值。
- 必须拉取显示窗口之前的预热历史；递归指标锚点为快照中最早可用历史，不能随图表翻页重新播种；返回 calculation_start。扩大数据起点会改变结果，须生成新快照并保留旧版本。
- 金叉定义：前一有效 bar 的 A≤B 且当前 A>B；死叉相反。跨停牌可用前一实际 bar，跨未知缺口则停止计算并报数据不足。

公式是本产品明确口径，不宣称与其他 App 默认值完全相同。测试必须包含人工可复算小序列、平价、跳空、缺值、分红拆股与不同预热窗口。

## 5. 一句话生成策略（S-04／S-09）

### 5.1 职责与状态

流程：用户文本＋当前标的＋最新草稿＋允许的指标／操作目录 → 模型提取明确要求、生成规则及回测配置建议 → 草稿结构与字段校验 → 展示已填策略卡／补充关键缺项 → 完整 DSL 严格 Schema 校验 → 语义编译／数据能力检查 → 保存版本／用户运行回测。不完整草稿可以展示和保存，不作为可执行 DSL 进入回测。

模型负责把语言映射成规则和解释；指标值、信号、订单、费用与收益由确定性引擎计算。模型不能发 HTTP、运行 Python／shell、查询他人策略、调用券商或更改交易规则。

生成状态：`queued → generating → validating → ready | needs_clarification | unsupported | failed | canceled`。ready 只表示草稿可解释且类型有效；能否在某区间回测还要通过数据与规则门禁。

- 面向不熟悉指标的用户，AI 可从 registry 提出指标、参数、阈值与条件组合，并自动填入规则卡；常用参数／回测默认值在 assumptions[] 列出。每项显示用户输入、当前上下文、系统默认、AI 建议或待补充的来源，以及必要的白话解释；建议不是最优参数结论。
- “合适时买入／风险小一点”等描述先给出可计算方案或简短选项；有歧义的关键含义每轮优先澄清 1～2 项。没有提及止损且未采用模板时展示待选择的止损安排；采用模板时明示模板预填的止损值，不能冒充用户指定，也不能静默记成用户选择了不启用。无歧义且完整展示的建议与默认值可随运行一并确认。
- 来源、解释、澄清项与修改差异保存在草稿元数据中，回测配置建议独立于策略 DSL；不得向执行 DSL 混入未声明的编辑元数据。模型生成配置建议也须通过对应字段白名单、类型、范围与能力校验；费用、交易规则及数据快照引用只能解析到服务端可用配置，不能接受模型伪造值。
- 自然语言和规则卡编辑更新同一草稿；指定局部修改时只修改目标字段及其必要依赖，展示差异，不覆盖无关字段和手动编辑。按最新 revision 合并后重新校验，失败保留上次有效内容；指标实际数值与回测绩效不得由模型预填。
- 用户指定的数字、标的、方向、区间不得静默替换。用户要盘中触价止损，不能悄悄改为收盘止损；不支持时说明原因和可选替代。
- 一个生成请求最多 2 次模型调用（第二次仅修复 Schema／编译错误），总 45 秒；超出失败，保留用户输入与上次有效版本，不无限自改。
- 策略修改使用 base_revision 乐观锁；基于旧版本的迟到模型响应不能覆盖当前版本。
- 用户点击运行即确认该规则卡与回测配置；无需每轮聊天再弹独立授权窗口，但未确认或有歧义草稿不能执行。

**策略市场合同（产品要求见 PRD §1.1、§3.6～3.7）：**

- 撤销三套示例模板作为首批必上架内容及统一 50% 仓位／5% 止损的要求。已有数字仅用于规则编辑与计算示例，正式市场内容需独立的来源、假设、完整参数及发布审核；不能自动把 fixture 或临时模型输出上架。
- 市场条目保留稳定 ID、不可变版本、来源／授权说明、假设、规则编辑结构及可执行 DSL、参数、支持范围、规则校验记录、可选历史回测证据引用、发布时间与上下架状态。规则通过与回测证据分别建模，回测记录必须与具体策略版本和输入 manifest 绑定。
- 首版平台维护发布目录，普通用户只读已发布内容；市场条目与用户私有策略分域，不得复用去掉 owner 条件的用户策略查询。公开回测证据采用审核后可展示的专用记录，不暴露其他用户私有运行或配置。
- 复制在服务端核验当前条目仍上架、源版本可用、规则校验通过且引擎支持，再创建带 owner 的独立草稿；来源身份放元数据，不向 strategy.v1 混入字段。复制接口有幂等键，失败不创建半份草稿；传入他人 owner 无效。
- 复制保留明确参数并显示来源；标的、费用、区间等按用户本次配置校验。原回测证据不变成用户运行；修改规则或标的后标待回测。AI 解释与修改仍遵守最新 revision、字段优先级和差异展示合同。
- 下架停止新复制，用户已有副本不级联删除，保留来源及下架提示；历史规则／数据的有效性依旧单独校验。无合格内容时返回真实空态，页面错误与空结果分别处理。

### 5.2 DSL 最低合同

既有 `strategy.v1` 保留读取与重放；新增编辑／引用操作数按阶段 B §12.4 的 `strategy.v2` 实现，不回写旧合同。JSON 对象未知字段拒绝；所有引用必须解析；禁止可执行字符串、任意函数、文件／网络／模块路径。

必需字段：`name, instrument_id, signal_period, price_basis, indicators[], entry, exit, position, risk, execution`。

- `signal_period` 初版可执行值 `1d`；周月可看图，若用户要求周月信号需明确返回当前能力不足，不能用日线冒充。后续按完整周期完成时间增加能力版本。
- `price_basis=raw|causal_qfq`，默认 causal_qfq；因子不足时不可静默退到 raw。
- `indicators[]` 为 `{id,type,params}`，类型仅 §4 registry；节点引用例如 `macd.dif / macd.dea / kdj.k / kdj.d / kdj.j / close / volume`，枚举字段受类型检查；volume 为已完成日线的成交股数。
- 条件为 `all/any/not` 组合及 `gt/gte/lt/lte/eq/crosses_above/crosses_below`；常数为 decimal string；`lag` 仅 0～250，不允许负数或未来索引。
- 最大 20 个指标实例、100 个条件节点、深度 8、周期参数 2～500；超限拒绝。eq 在内部数值口径下比较，不用 UI 文本相等。
- `position` 初版为目标权益比例 0～1，空仓入场、不加杠杆、不金字塔加仓；重复入场信号持仓时忽略并记录。
- `risk` 支持收盘检查的固定止损／止盈、最大持有 bar 数；stop_loss_pct / take_profit_pct 为 0～1 之间比例。可执行版本中空值表示明确未启用，不代表草稿中的待补充；AI 提议阈值须标注建议来源并经规则卡确认，不得冒充用户指定。
- `execution` 冻结为 `next_session_open`、退出优先、初版不做日内触价和复杂限价单。
- 编译输出 `normalized_rules, assumptions[], required_data[], warmup_bars, capability_errors[]`；模型解释不作为编译输入。

**可视化条件与连续窗口的编译合同：**

- 「同时满足／任一满足／取反」分别映射 `all/any/not`；保留括号层级，空组拒绝。比较操作沿用已有枚举，J 值阈值不裁到 0～100。
- 补全引用操作数的明确形式：`{"ref":"volume","lag":1}` 表示前一根已完成 bar 的成交量；裸字符串引用等价于 lag=0，常数继续使用 `{"constant":"20"}`。该对象形式仅在新增strategy.v2中声明，v1节点lag语义保持不变；前后端、AI与持久化按阶段B §12.4兼容，未知字段仍拒绝。
- 「连续 N 天满足」为条件编辑层的结构化配置，N 为 1～20；编译为 N 个滞后条件的 `all`，每项相对于当前信号日偏移 0～N−1。内部引用自带的 lag 叠加偏移；交叉还需额外前一根数据。仅作用于该条条件，不能连带移动同组其他条件。
- 「连续放量 3 天」编译为 `volume[0]>volume[1] AND volume[1]>volume[2] AND volume[2]>volume[3]`，与 `kdj.j[0]<20` 再组成外层 `all`。表达式仅为语义示意，实际存储使用类型化节点，不执行字符串公式。4 根比较 bar 是成交量条件的最低历史要求，整条策略还须覆盖 KDJ 预热。
- 连续窗口按所属交易所日历检查：休市日跳过，窗口含已知停牌或零成交日则连续条件为 false；未知缺口或未预热返回数据不足，不当 false。每个成交量比较的两侧均须为正且属于相邻交易日。该规则仅用于连续窗口，不改变普通交叉跨已知停牌的既有口径。
- 编辑层保存持续天数、快捷条件与分组信息，编译产物独立保存为可执行规则；二者同 revision、同次校验发布，回测只执行编译产物。AI 输出也进入同一编辑结构，不靠解析解释文本恢复窗口内容。展开后的 lag、节点数、深度仍受上文限额约束，超限提示精简。

### 5.3 模型接入与隔离

- 复用现有模型配置／协议 adapter／密钥保护的可复用组件；支持 `openai_chat_completions` 与 `openai_responses`，同配置版本固定一种协议，不能用自动切协议掩盖失败。
- 策略身份独立绑定 `owner_id, strategy_draft_id, generation_id, model_config_version, prompt_version, deadline, budget_scope`；`allowed_tools=[]`，模型仅生成 DSL。
- 现有代码中的 ModelProxy 与 research run/task 有耦合，不能假定直接可用。实现需通过独立策略适配入口复用底层传输／账本，或者在明确依赖下抽取共享组件；禁止创建假 research run 获取令牌。
- 策略生成用量按 `strategy_generate` 独立预算与审计，不扣研究次数，也不能免费绕过总费用限制。设计频率 10 次／用户／分钟、并发 1；金额上限从现有管理配置读取，缺配置不做付费 live。
- 所有协议传入相同 DSL Schema／指标目录／默认值；拒绝、截断、超时、usage unknown 明确处理。没有模型凭据时可验证受控样本，但不能声称一句话 live 生成已通过。
- 阶段 B 文档统一维护两条工作线；策略需求不改研究目录、研究三工具或公开 report Schema。确需共享代码适配时记录依赖，运行既有回归；策略交付和阶段 B 签收分别计算。

## 6. 历史模拟回测（S-05／S-10）

### 6.1 输入与复现

BacktestConfig 至少包含：`strategy_version_id, instrument_id, start, end, initial_cash, currency, fee_schedule_id, commission_config, slippage_bps, participation_cap, benchmark, data_snapshot_id, execution_profile_id`。

- 默认区间为截至最新完整交易日最近 3 年；不足则显示实际可用范围，用户确认后运行，不静默缩短请求区间。start/end 按包含边界处理，start 前只预热不交易。
- 数据准备先输出 coverage report；只有窗口、预热、停牌／公司行动／规则满足要求才进入 running。
- 冻结策略 DSL/hash、数据 manifest/hash、目录／日历／交易规则／费用／公司行动／指标／回测引擎版本。相同计算输入产生相同交易和结果 hash；运行 ID、时间戳不计入结果 hash。
- 模型生成阶段可以变化；回测阶段禁止调用模型作信号或收益计算。固定数据快照不等于具备历史时点可获得性，两者分别记录。

### 6.2 每日事件与模拟撮合

顺序固定：处理当日有效公司行动／可用持仓 → 执行前一日待执行订单 → 当日收盘估值 → 计算当日完整 bar 指标／风险与信号 → 形成下一交易日待执行订单。

- t 日收盘信号最早 t+1 所属交易所交易日开盘模拟成交，不可用 t 收盘生成信号又按 t 收盘成交。
- 原始开盘价为模拟基准；买入价上调、卖出价下调滑点，再按当日 tick 规则作不利方向取整。数据不足无法确定开盘或限制时，不成交并记原因。
- 每一订单区分 signal、submitted、filled／partially_filled／rejected／expired。单纯出现信号不增加收益。
- 目标数量依据 t 日收盘权益与目标仓位产生；t+1 若跳空或费用使现金不足，只按冻结规则向下缩量，不借钱、不用 t+1 收盘重新决定仓位。
- 设计默认滑点 10 bps、数量上限为前一有效交易日成交量的 1%；这些是模拟假设，不代表实际成交能力。t 日成交量不能在 t 日开盘用于下单决策；每日模拟成交总量亦不得超过当日实际量的保守校验上限。
- 撮合是日线近似，不假装知道开盘盘口。对数据无法验证的流动性／竞价排队单独标注；碰到封板等无法合理成交情形按保守规则拒绝。
- 入场订单仅下一个交易所交易日有效，停牌／拒绝后到期；退出意图可持续到可卖出，每日记录未执行原因，不无限保留过时入场信号。
- 初版只支持单一多头仓位，退出条件与风险退出冲突时合并一次退出，退出当日不重新入场；剩余未卖部分保留待退出状态。
- 固定止损／止盈以当前建仓周期的净收益率判断：分子为收盘持仓市值＋该周期已实现卖出净额＋已确认股息权益−累计买入含费金额，分母为累计买入含费金额。未收到的股息列应收，不作为可买入现金；现金到账后从应收转现金，不能重复增记权益。最大持有 bar 数从首次成交日计为 1。
- 回测结束不默认强平：按末日收盘计剩余持仓市值，单列未实现盈亏；末日信号不能生成区间外成交。需强平时作为独立配置与成本假设，不混算。

### 6.3 A／港股交易规则

交易规则以 `exchange＋board＋instrument＋effective_date` 选版本，不把今日规则套到所有历史日期。

| 维度 | 必需处理 |
|---|---|
| 买卖限制 | A 股适用的当日买入可卖限制；港股按其规则；持仓批次可卖数量与资金可用状态分开 |
| 申报数量 | 沪深各板块、北交所规则分别配置；港股每手股数按证券／日期读取；不能全部硬编码 100 |
| 价格约束 | 当日涨跌幅限制、无涨跌幅限制窗口、风险警示及临停状态；不能用单一 10%／20% 模板覆盖全市场 |
| 港股 | 柜台币种、历史每手／tick、半日市／停牌，不能套用 A 股涨跌停模型 |
| 公司行动 | 拆并股／送股调整持仓数量与成本，现金股息按权益登记和支付事件入账；不可用复权价再加分红导致重复收益 |
| 复杂事件 | 配股、换股、私有化／退市、资本返还、零碎股现金处置，未支持或缺关键数据时阻断跨事件回测 |
| 费用 | 佣金／最低佣金、适用税费与交易费用，按市场、买卖方向、金额取整及生效日期计算并逐项保存 |
| 币种 | 单次运行只用标的柜台币种；CNY 与 HKD 结果不可直接加总；跨币种组合需独立汇率／资金账本契约 |

费用表必须有来源／适用期，券商佣金由配置明确；不能把用户未填写或供应商未知的成本当 0。不存在覆盖所选历史区间的规则时返回 `RULE_DATA_INCOMPLETE`，不输出“已考虑真实交易成本”。

### 6.4 防止未来数据与复权误用

- 信号只读取当时已完成、已允许使用的数据，禁止负 lag、未来收益作入场条件、未完成周月 K 值、全区间统计后反填阈值。
- `causal_qfq` 在每个信号日 t 只纳入截至 t 已生效且当时可获知的公司行动，将历史窗口调整到 t 的基准后计算。发生因子改变时重算受影响指标历史，不能续用旧基准递归状态。
- 页面 `qfq` 可以展示最新基准的历史曲线，但与 causal_qfq 信号轨迹的差异必须标注。点击回测成交应展示该次运行的冻结指标／原始成交价格。
- 公司行动记录至少包含 effective_at、available_at、record_date／pay_date（适用时）及版本；没有这些信息，不能宣称历史时点精确回测。
- 历史修订数据与当时可获得数据分成 `historical_revised / point_in_time_verified` 两种证据级别；前者只能标为基于修订历史的研究模拟。已知用到未来信息的规则仍必须拒绝，不能用标签免责。
- 本版针对用户指定股票回测，不开展历史全市场选股。如果扩展选股／组合，必须有历史上市／退市与成分记录，不能把今天的全目录当过去股票池。

### 6.5 结果与绩效口径

结果必含：净值、权益／现金／持仓、回撤、逐笔订单与成交、信号、费用、分红、未成交原因、版本 manifest、数据质量、假设与基准。

- 总收益=期末权益／初始权益−1；年化按实际日历天数 365.25 折算，少于 365 天仍可计算但标「短样本年化」。
- 最大回撤由完整权益序列相对历史峰值计算；波动率／Sharpe 使用所属交易所日频权益收益、年化因子 252，rf 默认 0 并显式展示；样本不足或标准差为 0 返回 null 和原因。
- 胜率按已完成的一次建仓到清仓交易周期计算，盈亏包含分摊费用与分红；未平仓周期不加入胜率。零交易胜率为 null，不写 100%。
- 盈亏比、交易数、持有天数、换手、总成本分别说明分母；没有亏损样本时盈亏比返回 null，不输出 Infinity。
- 默认基准为同股票同区间买入持有，使用相同公司行动、成本与成交能力规则；指数基准需要独立数据能力，不能用价格指数冒充含分红总回报。
- 对比仅在区间、币种、数据快照和费用口径一致时直接排名；不一致时先列差异。不得模型挑选最好曲线隐藏失败／较差运行。
- 提供用户手动划定训练／样本外区间，冻结策略后评估样本外；本版不提供自动全市场参数寻优。调参次数／版本历史保留，回测不能被表述为未来收益保证。

## 7. 任务状态、限额与持久化（S-06／S-11）

### 7.1 异步运行

回测状态：`queued → preparing_data → running → succeeded | insufficient_data | failed | canceled`。终态单向，不允许取消后被迟到 worker 写回成功。

- API 创建任务返回 202，前端轮询状态并支持取消；进度是已处理 bar／总 bar 或明确阶段，不伪造百分比和完成时间。
- 同用户最多 2 个活动回测，全进程默认 2 个执行槽；每任务最多 10000 个日 bar（含预热）和 120 秒计算时间，数据准备单独最多 10 分钟；均为可配置工程上限，不能通过截断历史变成功。
- 数据准备按 provider 限流复用快照，不为每次回测重新爬全市场；用户不能用任意 symbol／URL 打开无限出站。
- 任务采用 DB 租约、心跳和 execution_epoch；重启后过期任务明确 failed/WORKER_RESTARTED，可用原输入新建重跑。重复 worker 不能重复提交账本。
- 幂等键 owner＋operation＋key，覆盖规范化请求 hash；同体返回原任务，异体 409；幂等命中不再扣模型／计算额度。
- 删除策略后禁止新回测，已有任务取消；用户自己的历史按删除策略清理。共享市场快照若被其他任务引用不删除；私有文本与生成缓存独立清理。

### 7.2 数据表责任

名称可微调，字段语义与唯一性不可丢失。所有新增表在策略／行情域，不扩研究 report。

| 表 | 必需内容与约束 |
|---|---|
| finance_market_instruments / aliases | 稳定 security、柜台、有效期、目录版本、检索索引 |
| finance_market_snapshots / bars | 不可变 manifest/hash、源版本、覆盖／质量、OHLCV；快照内 bar 唯一 |
| finance_market_actions / rules | 公司行动、复权因子、日历、交易约束／费用的有效时间与版本 |
| finance_strategy_drafts | owner、输入、生成状态、assumptions、DSL、revision、generation_id |
| finance_strategies / versions | owner、名称、当前版本；版本 DSL/hash／编译版本不可变 |
| finance_strategy_generations | owner、draft、模型／Prompt／预算版本、usage、状态、错误与幂等 |
| finance_backtest_runs | owner、策略版本、配置／manifest、状态、lease／epoch、进度／错误、幂等 |
| finance_backtest_orders / fills | signal_id、数量／价格／费用、成交／拒绝原因和事件时间 |
| finance_backtest_equity / results | 每日账本、指标、基准、结果 hash，与 run 关联 |
| finance_strategy_workspace | owner、最近标的、自选、图表布局与指标配置；不当作模型长期记忆 |

owner 从 Bearer 身份取得，不能信任客户端 owner_id。所有草稿／策略／回测读取、修改、取消、删除、导出带 owner 条件；他人 ID 返回 404。共享行情响应不得缓存用户策略、私有信号或研究事件。

## 10. 非功能与失败边界（S-13）

- 行情出站固定 allowlist，拒绝客户端 URL，校验重定向目标与私网地址；源 adapter 解码设 body／内存上限。
- 生成输入限长 4000 中文字符等价 UTF-8 文本预算，并受模型 token 上限校验；DSL 限额见 §5。策略文本作为数据，不能覆盖系统工具权限。
- live 没有凭据／预算／源契约时精确报依赖缺失；不借 fixture、缓存旧错误或模型猜测“补齐”。
- 回测结果原子发布，只有账本与指标全部校验后 succeeded；取消／失败可保留诊断进度，不展示为完整收益报告。
- 已知数据缺口阻断回测；不可核实成交能力的日线近似必须在结果中呈现假设。不能将无数据解释为零波动、无交易或成功零收益。
- 性能设计目标：目录搜索 p95≤300ms；热缓存 250 bar＋常用 3 指标 p95≤1s；5000 日 bar 单策略计算 p95≤5s（不含外网、冷数据准备）。验收记录机器配置、并发与样本，未测不称达标。
- UI 性能目标：至少 2000 根显示窗口可缩放，长历史按视口／分页加载；自动化验收外加真实桌面／平板／手机操作，不以截图代替交互。

### 12.1 必须加入的具体反例

1. `510300.SH` 是基金类型，不能因满足股票正则而当 A 股股票；`.BJ` 的实际上市股票必须能搜索和进入行情页。
2. HK 人民币柜台不能标 HKD；同一公司多柜台不得合并成一条错误价格序列。
3. 周一缓存 250 根，周二收盘完成后请求应有新一日；不能以数量足够无限命中旧缓存。
4. 因子更新只刷新后半段时必须拒绝发布拼接曲线；旧回测仍引用旧完整快照。
5. 港股半日市／收市竞价期间不能把未完成 bar 当最终值；正在形成的周月 bar 不进入回测。
6. 用户说“金叉买入”但未说明何指标时 needs_clarification；“MACD金叉”可用显式默认参数。
7. 用户要求“未来三天会涨才买”、读取文件或发送请求的策略必须拒绝，不能生成可执行表达式。
8. t 收盘出现信号，t+1 跳空导致资金不足时缩量／拒绝，不能按已知 t 收盘价回填成交。
9. A 股封板、停牌、可卖数量不足、HK 不足一手时保留明确未成交原因；不能每个信号都算交易。
10. 分红拆股只在已登记权益／有效日期记账；复权信号价不能直接乘实际股数生成资金。
11. 缺一段应交易日行情、未知历史费用或未支持的公司行动，运行 insufficient_data／failed，结果接口不提供完整绩效。
12. 模型／worker 取消后返回结果不能把状态改 succeeded；他人 run_id 导出返回404。
13. 将未来 bar 追加到输入时，过去已经生成的信号不能变化（固定当时可用数据）；对 latest-qfq 图表的变化单独测试，不能混淆。
14. 同样快照切显示日期、刷新页面不改变指标锚点；保存参数修改必须改变策略版本及输入 hash。
15. J=19 且最近 4 日成交量为 100、120、150、180 时，「J＜20 且连续放量 3 天」成立；J=20、任一日量相等或中途缩量时不成立。J=-5 是合法值；阈值也不得强制裁到 0～100。
16. 同一示例只有 3 根成交量 bar、KDJ 未预热或存在未知数据缺口时不能生成有效信号；已知停牌／零成交中断连续性，周末与交易所休市不计数。不得要求前三天 J 也小于 20。
17. 条件树在 AI→配置窗口→保存→重新打开后，all／any／not、lag、参数及分组语义保持一致；取消编辑不影响草稿，打开期间 AI 修改导致 revision 冲突时不得静默覆盖。

### 12.2 验证层级

- `offline`：fixture／黄金样本、数学、DSL、账本、鉴权与错误路径。
- `integration`：Vue→Go→DB／worker 的状态与取消、任务并发、页面真实交互；受控源明确标 test。
- `live-data`：真实目录／历史数据、能力和覆盖报告，保存允许范围内原始样本 hash。
- `live-model`：一句话生成的实际模型请求、映射正确性、usage／预算与失败路径；不以请求成功代替语义验证。
- `acceptance`：用户走完搜索→指标→一句话→编辑→回测→结果→重跑的完整案例并签收。

未来验证入口建议 `app/scripts/verify-strategy.sh {offline|integration|live-data|live-model|all}`，目前不存在也不声称已运行。退出码 0=通过，1=断言失败，2=环境／凭据／依赖阻塞，3=强制项 skip／证据不足。离线全绿不能记 live 或用户签收通过。
