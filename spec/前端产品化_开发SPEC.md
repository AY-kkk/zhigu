# 知股前端产品化 · 开发 SPEC

版本 FPROD-SPEC-1.0｜2026-10-12｜适用基线：`codex/futures-review-release`。

本文定义知股个人项目从“功能型工程界面”达到“完整、稳定、可正式使用的个人投研产品”的前端开发合同。前端产品化以已冻结的后端 API、错误码、能力状态和运行模式为输入，不承担用假数据掩盖后端缺口，也不要求在部署前具备真实供应商凭据。

本文与以下文件共同构成开发约束：

- [`后端生产化_开发SPEC.md`](./后端生产化_开发SPEC.md)：生产部署、服务状态、真实接入和运维合同；
- [`期货研究模块_开发SPEC.md`](./期货研究模块_开发SPEC.md)：期货业务对象、报告、证据和门禁；
- [`投研观点模块_开发SPEC.md`](./投研观点模块_开发SPEC.md)：观点研究体验与报告发布规则；
- `contracts/`、`app/contracts/`：机器可读契约；
- `app/web/src/`：现有 Vue 3 产品基线。

若页面设计与机器契约冲突，必须先修正契约或本文，不得由页面静默猜测字段、状态或权限。任何“看起来成功”的界面都必须有可核验的后端事实支持。

## 1. 优先级与交付顺序

### 1.1 开发优先级

| 优先级 | 工作流 | 前端开始条件 | 完成结果 |
|---|---|---|---|
| P0 | 后端生产化 | 立即开始 | API、状态、错误、部署和真实接入合同冻结 |
| P1 | 前端产品化 | P0 核心合同冻结；可与 P0 后段并行实现非接口工作 | 全部用户旅程、状态、视觉与质量门禁完成 |
| P2 | 整体部署 | P0、P1 均通过上线前验收 | 单机生产环境可用 |
| P3 | 真实接入 | 生产环境健康后 | 注入真实凭据并完成线上最小样本验证 |

P1 不意味着等待 P0 全部结束才开始编码；页面框架、设计系统和独立组件可以提前完成。但任何依赖 API 的页面只有在契约测试通过后才能计为完成。

### 1.2 唯一发布顺序

```text
后端组件与合同完整
  → 前端页面与交互完整
  → 全栈 fixture/契约/故障稳定性验收
  → 生产构建与单机部署
  → 线上注入真实数据和模型凭据
  → 真实链路验证
  → 个人正式使用
```

本项目不做灰度、不做 A/B、不做多租户和运营审批。`off/read_only/live` 仅用于故障控制、能力降级和防止不完整数据被误用，不表示分批放量。

### 1.3 前端发布门禁

| 门禁 | 含义 | 允许真实凭据缺失 |
|---|---|---|
| F0 组件完成 | 路由、页面、公共组件、API client、状态和关键操作齐全 | 是 |
| F1 产品完整 | 视觉、文案、响应式、无障碍和全状态体验通过 | 是 |
| F2 稳定性 | 单元、组件、契约、E2E、视觉和失败路径测试通过 | 是 |
| F3 可部署 | 生产构建、Nginx、缓存、安全头和同源 API 验证通过 | 是 |
| F4 真实可用 | 部署后真实来源与模型旅程通过，页面无 fixture 污染 | 否 |

## 2. 产品目标、用户与非目标

### 2.1 产品目标

交付一个面向项目所有者本人的中文个人投研工作台。用户能够在同一个产品中完成：

1. 登录并理解当前系统与各模块是否可用；
2. 发起股票观点研究，查看证据、事实核验、推理过程和报告；
3. 浏览策略市场、配置策略并理解行情来源与状态；
4. 查看事件情报、证据和回放；
5. 浏览期货品种、提交材料、发起研究、核验报告、保存假设并复盘；
6. 查看通知、能力、数据新鲜度和失败原因；
7. 在管理页完成模型、研究运行与期货来源配置。

最终体验必须像一个可每天使用的产品，而不是接口演示页、后台表单集合或功能清单。

### 2.2 目标用户

- 单一项目所有者，兼具普通用户与管理员能力；
- 主要使用桌面浏览器，移动端用于查看结果、通知和紧急操作；
- 能理解金融数据和研究报告，但不应阅读 JSON、日志或内部错误才能使用系统。

### 2.3 明确不做

- 注册、找回密码、邀请成员、团队空间、组织角色和租户切换；
- 社交动态、公开分享、收费订阅、营销增长和用户运营后台；
- 自动交易、下单确认、持仓同步或任何收益承诺；
- 原生移动 App、离线 PWA、推送服务或复杂动画；
- 为消除视觉差异同时重写全部历史模块；
- 新增第三套 UI 框架或为了“统一”进行无验收价值的大规模组件迁移；
- 在浏览器保存供应商 API key、模型 key 或 worker token。

## 3. 当前基线与产品化缺口

### 3.1 已具备

- Vue 3、Vue Router、Pinia、Vite、Axios 和 Playwright 基础；
- 登录、观点研究、历史、策略、事件情报、管理页和期货模块路由；
- 研究报告、证据抽屉、事实核验、推理链、材料上传等可复用组件；
- 期货概览、品种、发起研究、研究详情、假设、通知和来源管理页面；
- Semi UI 消费端组件、Element Plus 既有管理端组件和品牌素材；
- 用户切换时取消旧请求、generation 隔离和基础安全跳转。

### 3.2 必须消除的缺口

| ID | 当前风险 | 完成要求 |
|---|---|---|
| FG-01 | 页面更接近工程脚手架，首屏存在信息密度与留白失衡 | 建立统一工作台壳、页面标题区和内容栅格 |
| FG-02 | 期货页的完整业务状态和失败路径未形成产品合同 | 为每页定义 loading/empty/error/disabled/read-only/success |
| FG-03 | 来源管理依赖原始 JSON 输入的风险较高 | 默认提供结构化表单，JSON 仅作为高级导入 |
| FG-04 | 能力状态、数据时间和来源证据表达不一致 | 建立统一 Capability/DataFreshness/Provenance 组件 |
| FG-05 | 轮询、并发 loading 和错误存在共享状态风险 | 拆分资源状态，按请求 key 管理取消与竞态 |
| FG-06 | 生产 fixture 与真实模式在视觉上可能混淆 | 非生产 fixture 必须常驻标识，生产禁止 fixture |
| FG-07 | `package.json` 缺 lint、unit、component、a11y 门禁 | 引入最小测试工具链并纳入 CI |
| FG-08 | 大主包影响首屏，模块边界未全部懒加载 | 设定 bundle 预算并拆分图表、管理和研究详情 |
| FG-09 | 移动端、键盘和屏幕阅读器未成为验收项 | 达到本文响应式与 WCAG 2.2 AA 基线 |
| FG-10 | E2E 对正常链路有覆盖，但真实故障和重启恢复不足 | 增加全栈、故障注入和恢复旅程 |

## 4. 信息架构与导航

### 4.1 路由合同

保留现有 URL，避免无业务价值的迁移：

| 区域 | 路由 | 页面职责 |
|---|---|---|
| 登录 | `/login` | 登录、会话错误、安全重定向 |
| 观点研究 | `/app/research/new` | 发起研究、材料、确认成本与范围 |
| 观点报告 | `/app/research/:id` | 运行进度、报告、证据、事实核验 |
| 历史 | `/app/history` | 搜索、筛选、继续查看或删除 |
| 策略 | `/app/strategies` | 我的策略工作台 |
| 策略市场 | `/app/strategies/market`、`/:id` | 策略发现、行情与证据 |
| 事件情报 | `/app/intel/*` | 事件、关注、通知、证据与回放 |
| 期货概览 | `/app/futures` | 能力、品种、运行、假设和提醒摘要 |
| 期货品种 | `/app/futures/products/:productId` | 品种事实、合约、来源覆盖和研究入口 |
| 期货发起研究 | `/app/futures/research/new` | 材料解析、范围确认和任务提交 |
| 期货研究详情 | `/app/futures/research/:runId` | 进度、报告、证据、导出和失败处理 |
| 期货假设 | `/app/futures/hypotheses/:id` | 假设生命周期、校验条件和复盘 |
| 期货通知 | `/app/futures/notifications` | 告警、确认和定位上下文 |
| 期货来源管理 | `/admin/futures/sources` | 来源、权限、模式、健康与导入 |
| 研究管理 | `/admin/ai-settings`、`/admin/research-runs` | 模型设置与运行诊断 |

任何新页面先证明不能由现有路由内的 tab、drawer 或 dialog 承载。404 必须提供返回工作台入口，不得渲染空白页。

### 4.2 全局导航

- 桌面端使用固定侧栏加轻量顶栏；移动端侧栏变为可关闭抽屉；
- 一级导航只显示用户任务：研究、策略、情报、期货、历史；管理入口与用户入口分组；
- 当前路由、未读通知和模块状态可见，但不得把所有状态堆叠成仪表盘噪音；
- Header 显示页面名、环境/fixture 标记、核心能力异常和账号菜单；
- 跳转后焦点移动到主标题；提供可键盘触发的 skip link；
- 模块 disabled 时导航可以保留，但进入后必须解释原因和恢复动作，不得静默隐藏造成“功能消失”。

## 5. 统一产品语言与真实性

### 5.1 事实优先

每个数据型视图都必须在上下文中回答：

- 这是什么数据；
- 来源是谁；
- 截止/更新时间是什么；
- 当前是否完整、延迟或估算；
- 用户能否据此发布研究结论；
- 不可用时原因和下一步是什么。

不允许使用“已完成”“已同步”“可用”等模糊成功文案替代后端状态。金额、日期、比例、时区和品种代码必须使用统一格式化工具。

### 5.2 模式展示

| 模式 | 产品行为 |
|---|---|
| `off` | 页面只解释模块关闭原因，不发送写请求 |
| `read_only` | 允许查看历史与能力，写操作禁用并解释原因 |
| `live` | 按能力对象决定具体操作；并不等于所有来源健康 |
| `fixture` | 仅非生产可出现；全局常驻高可见提示，不得伪装真实数据 |
| unavailable | 模块壳可访问，显示依赖失败、request_id 和可恢复动作 |

生产构建接收到 fixture 数据时必须将其视为契约错误，页面显示阻断态并记录诊断，不渲染为普通报告。

### 5.3 金融表达

- 报告和假设是研究辅助，不是投资建议；关键详情页展示一次非打扰式声明；
- 方向、置信度、风险、反证和数据缺口必须同时出现；
- 禁止仅以红绿颜色传达涨跌、通过/失败或风险等级；
- 任何预测都显示观察期限、前提、生成模型/规则版本和引用时间；
- 缺证据时显示“证据不足”，不得用空白或默认正向文案替代。

## 6. 公共壳与设计系统

### 6.1 技术选择

- 消费端继续使用 Semi UI Vue 和 `editorial-tokens.css`；
- 既有管理页可暂留 Element Plus，但不得在同一页面混用两套基础控件；
- 新期货管理页优先沿用其所在管理壳的组件体系；
- 图表继续使用 lightweight-charts；
- 不增加新的 CSS-in-JS、状态库或通用 UI 框架。

### 6.2 布局规格

| 断点 | 布局 |
|---|---|
| ≥ 1280 px | 240 px 侧栏，内容最大宽 1440 px，12 列栅格 |
| 768–1279 px | 208 px 可收起侧栏，8 列栅格 |
| < 768 px | 顶栏 + 导航抽屉，单列内容，底部关键操作可吸附 |

页面顶部只保留完成任务所需的标题、摘要和主操作。不得使用高度超过可视区 35% 的无功能 Hero；研究工作台进入后应在首屏看到输入/状态或核心结论。

### 6.3 视觉与组件规则

- 正文默认 14–16 px，报告正文不低于 16 px，行高 1.5–1.75；
- 卡片、表格、分隔和阴影使用 token，禁止页面内散落相近但不同的颜色值；
- 每页最多一个主按钮；不可逆操作必须二次确认并显示影响范围；
- 原生文件 input 必须封装为可键盘操作的上传组件；
- 空状态说明为何为空，并且只在存在合法动作时显示 CTA；
- 骨架屏尺寸应接近最终内容，运行状态用文本和时间表达，不依赖无限旋转动画；
- Toast 仅提示短期结果；需要用户处理的错误必须留在页面中。

### 6.4 必须沉淀的公共组件

```text
app/web/src/components/workspace/
  AppShell.vue
  SideNav.vue
  WorkspaceHeader.vue
  PageHeader.vue
  RouteErrorBoundary.vue
app/web/src/components/system/
  CapabilityStatus.vue
  DataFreshness.vue
  ProvenanceSummary.vue
  RequestError.vue
  EmptyState.vue
  LoadingState.vue
  ModeBanner.vue
  ConfirmAction.vue
```

若现有组件已承担同一职责，应扩展现有组件而不是复制。公共组件只接受展示所需的归一化 view model，不直接发请求。

## 7. 页面产品合同

### 7.1 登录页

- 清晰展示产品名称、用途和当前环境；
- 支持 Enter 提交、密码可见性切换和提交中锁定；
- 401 使用账号/密码错误文案，网络失败不得误报凭证错误；
- 登录成功只跳转到 `safeInternalRedirect` 允许的内部地址；
- 会话失效时保留原访问地址，重新登录后返回；
- 不提供不存在的注册、找回密码或第三方登录入口。

### 7.2 观点研究工作台

- “新建研究”首屏展示研究问题、材料上传、研究范围和可用模型；
- 提交前确认预计预算、数据范围、模型和不可用能力；
- 研究详情展示运行阶段、取消、重试、证据、事实核验、推理链和最终报告；
- 运行中离开再返回可恢复当前状态；失败时保留已完成阶段和诊断标识；
- 历史页支持状态、时间和关键词筛选，删除使用服务端确认语义；
- 无真实模型时禁用提交而非生成 fixture 结果。

### 7.3 策略与行情

- 工作台区分“我的策略”和“策略市场”，并保留来源/版本/适用标的；
- 规则编辑器实时验证但不静默修改用户输入；
- 行情图显示周期、最后更新时间、交易时区和缺口；
- API 或 websocket 不可用时保留最后数据并明确标记陈旧，不画假 K 线；
- 策略证据和来源可打开，外链必须经过 SafeSourceLink 规则。

### 7.4 事件情报

- 事件列表支持来源、重要性、标的和时间筛选；
- 详情同步展示事实、来源、影响路径、反证和相关回放；
- demo 与 live 使用独立视觉标记和路由状态，不共享缓存污染；
- 通知可确认并定位到事件；来源缺失时不能发布肯定性结论。

### 7.5 期货概览

首屏按优先级展示：

1. 模块模式和阻断能力；
2. 数据新鲜度、最近失败和待处理通知；
3. 关注品种与可用合约；
4. 最近研究运行；
5. 活跃假设与临近校验条件。

每个摘要必须能进入对应详情。概览不复制完整报告，不展示无动作价值的服务内部指标。

### 7.6 期货品种工作台

- 标题区显示品种名、交易所、代码、交易时区和当前数据截止时间；
- 合约表区分主力、连续和具体合约，不混合价格口径；
- 分区至少包括：行情、期限结构、持仓/库存、来源覆盖、相关研究；
- 图表无数据时展示原因、请求范围和最后成功时间；
- “发起研究”携带当前品种与可验证的数据上下文；
- 来源覆盖不足时仍可浏览事实，但阻断不满足条件的研究提交。

### 7.7 期货发起研究

使用三阶段单页流程，不新增向导路由：

1. **问题与材料**：选择品种、输入问题、上传文件或添加安全链接；
2. **解析与核对**：展示抽取 claims、来源、时间、冲突和解析失败；
3. **范围确认**：选择允许的来源/模型，展示预算、数据缺口和提交条件。

提交必须携带 idempotency key。重复点击、页面刷新或网络重试不得创建重复 run。解析失败的单个材料可以重试，不必重传全部成功材料。

### 7.8 期货研究详情

- 时间线使用后端状态：`queued/running/verifying/succeeded/failed/canceled`；
- 运行中显示当前阶段、已耗时、预算消耗和取消操作；
- 取消中立即进入 `canceling` 本地过渡态，最终以服务端状态为准；
- 成功报告按照领域 SPEC 的固定章节渲染，不接受任意 HTML；
- 证据抽屉显示引用片段、来源、时间、权限、claim 关联和校验结果；
- 失败显示错误类别、可否重试、已保留产物和 request_id；
- 导出、保存假设等派生操作只有在服务端门禁允许时启用；
- 页面刷新、服务重启和浏览器休眠后能从服务端恢复状态。

### 7.9 期货假设

- 展示命题、方向、置信度、观察期、前提、反证和来源 run；
- 生命周期使用领域定义状态，不允许仅在前端改状态；
- 校验条件必须可读地表达指标、运算符、阈值、时间窗和数据来源；
- 用户确认、关闭、失效和复盘操作显示状态影响；
- 数据不足时显示 waiting/blocked，不将“无法计算”解释为条件未触发。

### 7.10 通知

- 支持未读、已读、需处理筛选；
- 每条通知展示发生时间、对象、严重级别、原因和目标链接；
- 批量已读允许乐观更新，失败时回滚并提示；
- 删除或不存在的对象显示上下文摘要，不进入无限 404 循环；
- 关键故障通知不能只靠颜色表达。

### 7.11 期货来源管理

- 默认使用结构化表单编辑名称、类型、覆盖品种、权限、模式、刷新策略和 endpoint ref；
- secret 只能选择或填写 secret reference，保存后永不回显原值；
- JSON manifest 仅作为“高级导入”，先解析预览差异，再明确确认；
- 列表展示健康、最后成功、数据截止、权限、模式和最近错误；
- 测试连接是独立、限时、可取消动作，不自动保存配置；
- 删除前显示受影响品种、计划任务和研究能力；
- `live` 切换必须由后端校验权限和探针结果，前端不能绕过。

## 8. 状态管理与请求并发

### 8.1 Store 边界

期货单一 `store.js` 必须按资源拆分，建议职责如下：

```text
modules/futures/stores/
  capability.js       模式、能力与健康
  products.js         品种、合约、关注列表
  research.js         草稿、材料、run、轮询
  hypotheses.js       假设与条件
  notifications.js    通知、未读与确认
  sources.js          管理端来源配置
```

拆分目标是避免一个请求覆盖全模块 `loading/error`，不是追求文件数量。简单只读状态可保留在组件内。

### 8.2 资源状态

每个异步资源至少维护：

```js
{
  data: null,
  status: 'idle' | 'loading' | 'refreshing' | 'success' | 'empty' | 'error',
  error: null,
  requestId: null,
  updatedAt: null
}
```

首次加载与后台刷新必须区分；刷新失败时可保留旧数据并标记 stale。账号切换、登出和路由身份变化必须取消旧请求并清空敏感状态。

### 8.3 竞态与轮询

- 所有可取消请求使用 `AbortController`；
- 使用账号 generation + 资源 request key 双重防止旧响应覆盖；
- run 活跃时默认 2 秒轮询，30 秒后退避到 5 秒，5 分钟后退避到 10 秒；
- 页面不可见时暂停普通轮询，恢复可见后立即刷新；
- 完成、失败、取消、404 或账号切换时停止轮询；
- 创建研究、导出、删除、模式切换等有成本/副作用操作不得自动重试；
- GET 可对网络错误执行最多两次指数退避，4xx 不重试。

## 9. API client 与错误合同

### 9.1 client 分层

```text
src/utils/http.js                 鉴权、request_id、统一 envelope、401
src/modules/futures/api.js        纯请求函数与参数序列化
src/modules/futures/stores/*      缓存、并发、乐观更新和业务状态
pages/components                  view model 与交互，不拼 URL
```

禁止页面直接调用 Axios。所有 query 参数必须通过 serializer；所有外部 URL 必须经过安全链接组件。

### 9.2 错误映射

前端依据后端稳定 `code` 决定操作，禁止依赖自由文本：

| 错误族 | 页面行为 |
|---|---|
| `UNAUTHENTICATED` | 清理会话并跳转登录，保存安全返回地址 |
| `FORBIDDEN` | 显示权限说明，不循环重试 |
| `VALIDATION_FAILED` | 聚焦错误摘要并映射到字段 |
| `CONFLICT` | 刷新当前对象，展示发生变化的字段 |
| `CAPABILITY_DISABLED` | 显示 ModeBanner 和恢复条件 |
| `SOURCE_UNAVAILABLE` | 保留可用旧数据，标记来源与最后成功时间 |
| `BUDGET_EXCEEDED` | 阻断提交，显示预算事实，不建议绕过 |
| `RATE_LIMITED` | 显示可重试时间；GET 可按 header 延迟重试 |
| `RUN_NOT_RETRYABLE` | 隐藏重试按钮，解释保留产物 |
| `INTERNAL_ERROR` | 通用安全文案 + request_id，不显示堆栈 |

未知 code 使用安全通用错误，同时上报诊断；不得崩溃、显示 `[object Object]` 或吞掉失败。

## 10. 表单、上传、报告与导出

### 10.1 表单

- 服务端是最终校验权威；客户端校验用于快速反馈；
- 提交失败保留用户输入，成功后才清空；
- 每个字段有可关联 label、帮助文本和错误文本；
- 日期时间明确使用北京时间或交易所时区；
- 数值输入明确单位，不允许仅靠 placeholder 表达；
- 离开包含未提交修改的管理表单时提示确认。

### 10.2 文件上传

- 上传前展示允许的类型、单文件/总大小和数量限制；
- 校验 MIME、扩展名与服务端返回，不信任浏览器文件名；
- 显示单文件进度、取消、失败和重试；
- 上传成功后显示服务端材料 ID、解析状态和安全文件名；
- 删除文件需同步删除服务端暂存对象；
- 预览不得执行脚本、宏或任意 HTML。

### 10.3 报告渲染

- 报告由结构化字段渲染；若接收 Markdown，使用仓库统一 sanitizer；
- 禁止 `v-html` 渲染未消毒的模型或来源内容；
- 引用序号可跳转证据抽屉并可返回原阅读位置；
- 报告更新时显示 revision，避免用户复制过期版本；
- 下载使用服务端文件名白名单，创建的 Object URL 使用后立即 revoke；
- 导出文件包含版本、生成时间、数据截止、来源摘要和风险声明。

## 11. 响应式、无障碍与浏览器支持

### 11.1 验收视口

必须在以下视口无横向页面滚动、关键操作不遮挡：

- 1440 × 900：主桌面工作台；
- 1024 × 768：小屏桌面/平板横屏；
- 390 × 844：主移动验收；
- 320 × 568：最小重排能力。

宽表格在移动端转为信息卡或局部可滚动区域，并提供列名上下文。报告、证据和研究进度必须在移动端可查看；复杂来源配置允许提示建议桌面操作，但不得白屏。

### 11.2 WCAG 2.2 AA 基线

- 所有功能可用键盘完成，焦点顺序与视觉顺序一致；
- 可见焦点环不被 reset；dialog/drawer 正确困住并恢复焦点；
- 文本与背景、非文本控件达到 AA 对比度；
- 状态变化通过 `aria-live` 适度播报，不高频朗读轮询；
- 图表提供文字摘要和关键数据表；
- 图标按钮有可访问名称；
- 错误摘要可跳转字段；
- 触控目标建议不小于 44 × 44 px；
- 尊重 `prefers-reduced-motion`；
- 页面标题随路由更新且唯一。

### 11.3 浏览器

支持当前及前一个主要版本的 Chrome、Edge、Safari。Firefox 作为非阻塞兼容检查。生产不支持 IE 或内嵌旧 WebView。

## 12. 性能预算

### 12.1 构建预算

| 指标 | 门禁 |
|---|---|
| 首次公共 JS | ≤ 350 KB gzip |
| 单个懒加载路由 JS | ≤ 180 KB gzip；超出需记录原因 |
| 首次 CSS | ≤ 100 KB gzip |
| 单张非报告图片 | ≤ 250 KB，优先 WebP/AVIF |
| sourcemap | 不公开部署；保留私有构建产物 |

必须懒加载期货、事件、策略图表、管理页和大型报告组件。不得为了降低数字复制同一依赖到多个 route chunk；CI 输出 chunk 报告并检查回归。

### 12.2 运行预算

在生产构建、本地 fixture 全栈和桌面中端设备条件下：

- 登录后工作台 LCP ≤ 2.5 秒；
- 可交互 ≤ 3 秒；
- 路由切换到 skeleton ≤ 150 ms；
- 长任务不得连续阻塞主线程超过 200 ms；
- 研究进度页面连续运行 30 分钟无无界计时器、请求或 DOM 增长；
- 浏览器休眠恢复后不形成轮询风暴。

外部真实接口耗时不计入静态资源预算，但必须有可感知进度、超时和取消。

## 13. 安全与隐私

- 浏览器只持有用户会话，不持有 provider、模型、内部服务或数据库凭据；
- 生产 API 使用同源 `/api`，不得把内部 worker URL 编译进前端；
- 保留安全内部跳转规则，所有来源链接限制为 `http/https` 并使用 `noopener noreferrer`；
- 用户输入、模型输出和来源内容默认按文本处理；HTML 必须经过白名单 sanitizer；
- 登录失败、报告错误和埋点不得泄露 secret、token、完整材料或数据库细节；
- 管理写操作防止重复提交并携带后端要求的 CSRF/鉴权机制；
- 前端生产环境不得通过 debug flag 绕过角色、能力或发布门禁；
- CSP、HSTS、X-Content-Type-Options、Referrer-Policy 和 framing 策略由 Web/Nginx 合同统一验证。

### 14.4 E2E 核心旅程

1. 登录 → 发起观点研究 → 运行完成 → 查看证据 → 导出；
2. 登录 → 浏览策略 → 查看行情与证据 → 创建/修改策略；
3. 登录 → 查看事件 → 打开来源 → 确认通知；
4. 登录 → 期货概览 → 品种 → 上传材料 → 解析核对 → 发起研究；
5. 运行中刷新/休眠/恢复 → 成功 → 保存假设 → 校验/复盘；
6. run 失败 → 保留部分产物 → 合法重试或显示不可重试；
7. 来源不可用 → 页面降级 → 管理页诊断 → 恢复后刷新；
8. `read_only` → 写操作禁用 → 恢复 `live` 后不刷新整站即可使用；
9. 用户登出或会话过期 → 请求取消 → 重新登录安全返回；
10. 手机视口查看报告、证据、通知和取消操作。

### 14.5 视觉与无障碍测试

- 对登录、公共壳、研究新建/详情、期货 7 个页面和来源管理建立稳定截图；
- 只对确定性 fixture 截图，隐藏动态时间但不得遮盖业务状态；
- 1440、1024、390 三档纳入 CI，320 做人工冒烟；
- axe 在关键页不允许 critical/serious 问题；
- 每个里程碑完成后用键盘和 VoiceOver/Safari 人工验收一次核心旅程。

### 14.6 失败注入

必须验证：慢网、离线、401、403、409、429、500、worker 超时、数据库重启、来源过期、模型拒绝、文件解析部分失败、重复提交、旧响应晚到、浏览器后台 10 分钟、run 在服务重启期间继续。

失败验收标准不是“不崩溃”，而是状态真实、动作合法、输入和可恢复产物不丢失。

## 18. 完成定义

前端产品化只有同时满足以下条件才算完成：

1. F0–F3 的 `FPR-01` 至 `FPR-43` 全部有自动化结果或签字证据；
2. 没有空白路由、占位按钮、静默失败、假成功或生产 fixture 回退；
3. 所有页面完整覆盖加载、空、错误、能力关闭、只读、成功和陈旧状态；
4. 观点、策略、情报和期货核心旅程没有回归；
5. 响应式、键盘、屏幕阅读器和性能预算达到本文门禁；
6. 生产构建可与后端整体部署，且真实接入只需要配置和探针，不需要改前端代码；
7. 部署后完成 `FPR-44` 至 `FPR-46`，才宣布系统进入个人正式使用。

F4 真实探针在上线前允许明确记录为 `NOT_RUN`，不得记为通过；除此之外，正常测试、错误路径和可部署性验收不允许以“个人项目”为理由跳过。
