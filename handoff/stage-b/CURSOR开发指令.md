## 不得变更的任务

- 产品仍是“粘贴 A 股单公司观点→人工确认→证据与反证报告”，不是二期自选股/长期记忆。
- GoSaaS 管账号、权限、配置、预算、数据和发布；Eino 是唯一总 DAG；DeerFlow 真正执行两个独立、有界研究 Loop。
- 不新增平行用户体系、第二套后台、第二个 Supervisor；不凭仓库目录或 import 宣称框架已接入。
- Python 没有供应商真实 Key/业务 DB 权限；消费者不直连 Python；全部模型和数据请求经过 Go 的能力与预算出口。
- 后台protocol枚举为 `openai_chat_completions` / `openai_responses`，共用模型控制面和账本；Go提供对应两个内部入口。按SPEC第6.1节实现请求/结果/工具ID/上下文/usage适配，禁止静默协议兜底或另建Responses研究循环。
- 不使用 fixture 兜底 live；不吞异常变“证据不足”的成功报告；不展示未通过闸门的草稿。
- 不改 `references/`；保留用户未提交改动，不自动清理、重置、提交、推送或部署公网。
- 不因本指令自行启用并行子 Agent；如用户另外授权，才按明确文件责任拆分。

## 第一轮必须交回什么

先读文档、识别当前基线和未提交改动，交回一页开工检查，包含：

1. Git SHA、工作树改动摘要；实际启动入口、GoSaaS 账号/角色接入点。
2. G0 的 A 修复复核证据；若用户尚未授权该复核或基线不完整，列为阻塞，不假定通过。
3. D-01～D-07 的 ready/blocked 状态。凭据由用户安全配置，不让用户把 Key 粘进对话。
4. B-ID 对现有文件/待新增文件的映射；协议差异和迁移清单，特别是双模型协议适配/后台protocol字段、控制协议header、记录句柄登记和私有报告检查记录。
5. 当前可执行关口、首批精确测试名称、预期失败断言；不要直接一次性实现整套系统。

没有用户签收 SPEC 或未满足关口依赖，不进入对应应用实现/真实付费调用。可以报告隔离兼容性探索的结果，但不能据此标完成。

## 每个关口的工作节奏

1. 写出本关涉及 B-ID、文件、输入/输出与验收断言，确认不需要临时猜供应商或扩大产品范围。
2. 先写有真实失败断言的测试，运行并记录业务红灯。编译/网络/安装失败是环境阻塞，不算正确的红灯。
3. 最小实现。测试直接验证真实执行路径与副作用，不能检查代码字符串、固定true、手工增加计数器来冒充行为。
4. 跑本关测试和受影响回归；状态/权限/预算使用真实 PostgreSQL 并发测试，Harness检查最终装配与实际invoke。
5. 按证据包格式保存实际命令、退出码、trace与账本，更新 `app/IMPLEMENTATION_STATUS.md`，提请复核。
6. 本关未通过不把问题顺延到下一阶段。只能写 `blocked` 或 `ready_for_review`，最终 accepted 由用户/指定复核者决定。

## 必须暂停并提出明确问题的情况

- 不清楚合法授权、模型/数据供应商、展示权限或真实调用费用上限。
- 当前真实 GoSaaS 入口/身份与文档不一致，需迁移已有用户或移动大量代码。
- 固定 DeerFlow 装配无法做到任务级模型注入、三工具白名单或中间件隔离。先报告源码位置与最小补丁方案，不能另写 Loop 冒名交付。
- 必须变更公开 Schema、增加Chat/Responses之外的模型协议、硬预算、作用域、结果语义或质量验收阈值。已明确的双协议实现不需要重复请求选型批准。
- 需要安装新服务、扩大网络/数据权限、公开部署、购买 API 或将私有数据发往额外第三方。
