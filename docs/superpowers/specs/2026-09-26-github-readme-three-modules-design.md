# GitHub README 三大核心模块介绍设计

状态：方案 A 已获用户确认，待用户审阅本设计文档后实施。
范围：仅调整 GitHub 仓库根目录 `README.md` 的项目介绍与媒体展示；不修改业务代码、API、路由或数据库。

## 目标

将 README 从“单一观点辨析 Agent”升级为当前完整产品介绍，使首次访问者在一页内理解：

1. 知股现在包含哪些核心模块；
2. 每个模块解决什么问题；
3. 最近的真实交互如何运行；
4. 开发者如何启动、测试和继续阅读文档。

## 三大核心模块

| 模块 | 用户任务 | 介绍重点 |
| --- | --- | --- |
| 投研观点 | 输入投资观点，获得支持、反证、未知项与可追溯证据 | 主张拆解、双路研究、证据边界、报告追问 |
| 交易策略 | 创建、编辑、保存并回测交易策略 | 可编辑规则、确定性回测、版本与来源、策略市场 |
| 事件追踪 | 关注公司与事件，追踪变化和证据 | 关注范围、事件流、证据时间线、事件详情、变化追踪 |

命名约束：

- 对外统一使用“事件追踪”，不再使用“事件情报”作为核心模块名称。
- 本设计不改写现有代码中的 `intel` 包名、URL、表名或历史文档标题，避免扩大改动范围。

## 页面信息架构

按以下顺序组织根目录 README：

1. **Hero**：项目名称、定位一句话、CI 与技术栈徽章。
2. **最近交互**：展示 `artifacts/intel/投资事件情报演示_60s.webm`，提供完整视频回退链接。
3. **三大核心模块**：三栏或三个连续小节，每栏只保留用户任务、能力与证据边界。
4. **产品边界**：不执行交易、不提供收益承诺、模拟/fixture 与真实能力分开表述。
5. **技术架构**：保留 Vue、Go、Python、PostgreSQL 的职责与数据流。
6. **快速开始**：精简运行命令与本地演示入口。
7. **项目结构**：更新三大模块对应的代码入口。
8. **文档导航**：链接 PRD、SPEC、验证与实现状态。
9. **贡献与许可**：保留现有合规入口。

## 文案原则

- 先讲用户能完成的任务，再讲工程实现。
- 三大模块均说明“能做什么”和“不做什么”，避免把计划能力写成已交付能力。
- “事件追踪”负责变化发现与证据追踪，不推断产业链，不直接给出交易指令。
- 策略规则由确定性服务计算和回测；AI 是可编辑入口，不执行任意 AI 代码。
- 观点研究明确保留支持、反证、未知项和证据不足状态。

## 改动文件

1. 根目录 README 明确出现且仅重点展示三大模块：投研观点、交易策略、事件追踪。
2. 最近交互视频位于三大模块介绍之前，并存在可点击的完整视频回退链接。
3. README 不再包含旧“产品界面”章节或旧交互界面截图。
4. 视频链接与所有文档链接在公开仓库中可解析。
5. README 文案区分真实能力、fixture/演示能力和未验收能力。
6. `git diff --check`、公开树检查和现有测试不受影响。
