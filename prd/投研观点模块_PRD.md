# 投研观点模块 PRD

版本：V1.0  
日期：2026-09-27  
状态：产品需求基线，不代表功能已经实现或通过验收  
范围：手动输入观点、上传研报、生成质证报告的 MVP

---

## 1. 产品定位

用户提交一条投资观点、一份研报，或两者同时提交。系统使用行情、财务三表、公告和上传研报，对观点进行事实核验、反证检索和推理链审查，最终生成可追溯的质证报告。

一句话目标：

> 帮用户分清哪些是事实、哪些是推演、哪些只是判断，并说明观点可能在哪里出错、什么证据会推翻它。

本模块不是投资顾问，不提供买卖建议、目标价或收益承诺。

---

## 2. 产品边界

### 2.1 本期做什么

- 支持手动粘贴投资观点。
- 支持上传研报，作为研究材料和事实证据。
- 支持从研报中抽取核心观点并进行质证。
- 使用行情、财务三表、公告和上传研报检索证据。
- 输出固定结构的质证报告。
- 允许查看引用原文、下载报告和重新研究。

### 2.2 本期不做什么

- 不提供研报、点评文章旁的一键 Challenge 入口。
- 不使用任意互联网搜索或新闻作为事实来源。
- 不做多研报横向比较。
- 不提供交易指令、组合建议或目标价。
- 不把模型判断包装成确定性事实。
- 不以 fixture、mock、截图或单元测试代替真实验收。

---

## 3. 目标用户

| 用户 | 核心任务 |
|---|---|
| 买方研究员 | 快速核验卖方观点中的事实、推演和风险 |
| 基金经理 | 判断一条投资逻辑能否进入正式研究 |
| 投资顾问 | 获得带来源、可转发的研究质证材料 |
| 个人投资者 | 避免只看到单一叙事，了解反证和证伪条件 |

---

## 4. 输入设计

系统支持三种输入方式。观点和研报至少提交一项。

| 输入方式 | 观点文本 | 研报文件 | 系统行为 |
|---|---:|---:|---|
| 只提交观点 | 必填 | 无 | 从行情、财务三表和公告检索证据 |
| 只提交研报 | 无 | 必填 | 抽取核心观点，研报同时作为被质证对象和证据 |
| 观点与研报 | 必填 | 必填 | 观点用于聚焦，研报用于立论和辩驳 |

### 4.1 观点文本

- 长度：20–2,000 字。
- 必须围绕一家可识别的 A 股或港股公司。
- 可以包含事实、推演、判断或投资结论。
- 用户可以手动指定标的公司和研究期限。
- 修改已解析文本后，必须重新解析并确认。

### 4.2 研报文件

- MVP 支持 PDF、DOCX、TXT。
- 单文件不超过 20 MB。
- MVP 每次研究支持 1 份研报；多研报输入属于 P1。
- 扫描件 OCR、复杂表格还原属于 P1。
- 上传后必须保存文件名、文件类型、上传时间、内容哈希、页码或段落定位。
- 文本提取失败时不得伪造摘要，应提示用户改传可复制文本的文件。

### 4.3 自动解析结果

提交后，系统应识别并展示：

- 标的公司；
- 研究期限；
- 核心观点；
- 事实主张；
- 推演主张；
- 假设或判断；
- 关键数字、单位和期间；
- 无法确定或需要用户确认的内容。

解析结果必须由用户确认后，才能创建正式研究任务。

## 5. 证据设计

### 5.1 固定证据源

MVP 只使用以下来源：

1. 行情数据；
2. 财务三表及结构化财务指标；
3. 公司公告和交易所披露；
4. 用户上传的研报。

暂不使用新闻、社交媒体、任意网页搜索或未审核的数据源。

### 5.2 研报的双重角色

上传研报可以同时作为：

- **被质证对象**：其中的观点、推演和遗漏需要被检查；
- **事实证据**：其中的数据、原文陈述和引用可以直接支持或挑战结论。

研报证据必须显示来源等级：

| 来源等级 | 示例 | 使用规则 |
|---|---|---|
| 官方披露 | 年报、公告、交易所披露 | 可作为高可信事实 |
| 结构化数据 | 行情、财务三表 | 必须注明指标、期间、单位和口径 |
| 用户研报 | 上传的券商或内部研报 | 可直接支持结论，但必须标记为用户提供的材料 |

用户研报不得伪装成官方披露。报告必须区分：

- 研报原文陈述；
- 研报作者判断；
- 可独立核验的事实；
- Agent 的推演。

### 5.3 证据记录

每条证据至少包含：

- `evidence_id`
- 来源类型和来源等级
- 标题
- 发布日期
- 获取日期
- 原文定位
- 来源链接或上传文件定位
- 原文摘录
- 指标、数值、单位和期间
- 内容哈希
- 数据版本
- 是否经过独立核验

### 5.4 引用规则

- 事实和推演必须引用证据。
- 没有证据时写“未找到有效证据”。
- 不得编造来源、链接、数字或原文。
- 不得用标题或摘要代替需要原文支持的事实。
- 研报中的引用只能作为线索；MVP 不自动访问其外部链接。
- 同一证据可以支持一条主张，同时挑战另一条主张。

## 6. 核心流程

```text
提交观点 / 研报
      ↓
解析标的、主张、推演、数字和期限
      ↓
用户确认或修改解析结果
      ↓
支持方检索并登记证据
反证方检索并登记证据
      ↓
逐主张核验与推理链检查
      ↓
合成质证报告
      ↓
程序校验引用、数字、日期和结构
      ↓
发布报告
      ↓
查看证据、下载或重新研究
```

### 6.1 用户确认

确认页必须展示：

- 标的公司；
- 研究期限；
- 核心观点；
- 关键主张；
- 将使用的证据源；
- 预计额度或成本；
- 数据截止时间。

默认不自动发送。用户可以修改标的、期限和研究重点。

### 6.2 研究过程

系统内部执行两个独立角色：

- **支持方**：寻找能够支持观点的事实和推演；
- **反证方**：寻找最强反证、替代解释和被忽略的风险。

两个角色不得共享未完成的结论。支持方失败不能被解释为反证成立。

### 6.3 程序校验

发布前必须校验：

- 所有引用均来自本次已登记证据；
- 事实和推演均有引用；
- 重大数字与证据中的数值、单位和期间一致；
- 不使用研究截止时间之后的信息；
- 未找到证据的内容没有被写成确定事实；
- 报告包含规定的七个结构块；
- incomplete 报告不得显示总体结论。

---

## 7. 报告结构

每份报告必须包含以下七块。

### 7.1 核心判断

只能使用以下状态之一：

- 支持；
- 部分支持；
- 被挑战；
- 证据不足。

核心判断必须说明结论覆盖哪条主张，不能把事实成立直接等同于投资结论成立。

### 7.2 事实核验表

每条事实使用以下状态：

| 状态 | 含义 |
|---|---|
| 成立 | 有充分、口径一致的证据 |
| 被前置 | 事实可能成立，但结论依赖尚未证明的前置条件 |
| 不成立 | 证据直接否定该事实 |
| 存疑 | 证据冲突、口径不明或材料不足 |

每行必须包含原文主张、核验结果、证据引用和原因。

### 7.3 逐条质疑

列出最重要的反方论据，包括：

- 与原文相反的证据；
- 被选择性忽略的数据；
- 不合理的比较基准；
- 一次性损益被当作持续改善；
- 利润与现金流方向不一致；
- 研报没有解释的关键变化。

### 7.4 推理链缺口

按 `A → B → C` 展示观点的传导链，并指出：

- 哪些环节有证据；
- 哪些环节只是推演；
- 缺少哪项数据或因果解释；
- 补齐后是否可能改变结论。

### 7.5 被忽略的风险

至少检查：

- 经营风险；
- 现金流风险；
- 资产负债风险；
- 一次性损益；
- 行业和竞争风险；
- 政策和监管风险；
- 时间与预期差风险。

没有发现有效风险时写“未发现新的有效风险”，不得编造风险。

### 7.6 证实与证伪条件

每条条件必须包含：

- 跟踪指标；
- 当前基线；
- 证实方向；
- 证伪方向；
- 观察时间点；
- 触发重新评估的动作。

### 7.7 证据清单

列出所有被报告使用的证据，并展示：

- 来源等级；
- 标题；
- 发布日期；
- 原文定位；
- 数据口径；
- 链接或文件位置；
- 支持或挑战关系。

---

## 8. 状态与异常

| 场景 | 系统行为 |
|---|---|
| 没有可核验观点 | 提示用户补充观点或改做“材料核验” |
| 未找到反向证据 | 明确写“未找到有效反证” |
| 证据冲突 | 标记冲突，不用单一模型结论强行覆盖 |
| 文件无法解析 | 保留原文输入，允许重新上传 |
| 余额或额度不足 | 创建任务前阻止，并说明未扣费 |
| 任务超时 | 显示已完成部分，不发布总体判断 |
| 中途取消 | 终止任务，并说明是否已扣费 |
| 网络中断 | 刷新后恢复查看任务状态 |
| 服务重启 | 已完成结果保留；未完成任务标记失败并允许重试 |
| 重新研究 | 创建新任务，不覆盖旧报告 |

---

## 9. 合规要求

- 结论页常驻“本报告仅供研究参考，不构成投资建议”。
- 不使用“推荐买入”“目标价”“保证收益”等措辞。
- 上传研报只展示必要短摘录，不大段转载受版权保护的全文。
- 用户上传材料按私人研究数据处理，不用于公共内容。
- 预填或复制内容时清除电话、邮箱等非必要个人信息。
- fixture 数据必须清楚标记，不得作为真实投资证据。
- 模型置信度不能替代来源、日期和证据等级。

## 10. 优先级

### P0：MVP 必须完成

- 三种输入方式；
- 标的、主张、事实、推演和数字解析；
- 用户确认；
- 支持方与反证方研究；
- 行情、财务三表、公告和上传研报证据登记；
- 七块质证报告；
- 引用查看；
- 单文件 HTML 报告下载；
- 取消、失败、重试和重新研究；
- 固定免责声明；
- 证据、数字、日期和引用程序校验。

### P1：增强

- 多份研报输入与对比；
- 扫描件 OCR 和复杂表格还原；
- 原文页码高亮；
- 流式研究步骤；
- 断线后恢复执行；
- 保存到工作区；
- 成本预估与模型档位；
- 链接有效性自动抽检。

### P2：后续

- 文章详情页一键质证；
- 段落级质证；
- 同文缓存；
- 智能追问；
- 标的名单核查；
- 更多外部数据源。

## 11. 验收标准

### 11.1 功能验收

- 只提交观点、只提交研报、观点与研报同时提交均能完成研究。
- 上传研报中的核心观点能被抽取、确认和逐条质证。
- 研报中的事实可以直接支持结论，但来源等级和独立核验状态清楚可见。
- 报告完整包含七个结构块。
- 每条事实和推演都能打开对应证据。
- 修改观点后不能继续使用旧解析结果。
- 取消、超时、失败和重新研究路径均可用。
- incomplete 报告不显示总体判断。

### 11.2 质量验收

使用不少于 50 条人工评测样本：

- 事实错误率 ≤ 3%；
- “质疑是否击中要害”平均分 ≥ 4/5；
- 可溯源论据占比 ≥ 90%；
- 抽检来源链接有效率 ≥ 95%；
- 数字、单位和期间错误为 0；
- 编造来源或原文为 0。

### 11.3 性能验收

- 文本解析 P90 ≤ 2 秒；
- 创建任务后首个过程事件 P90 ≤ 5 秒；
- 普通文本或可提取文本研报端到端 P90 ≤ 90 秒；
- OCR 和复杂扫描件不计入上述 P90，但必须显示处理进度。

### 11.4 工程验收

- 必须完成真实 Vue → Go → 数据源 → 证据登记 → worker → 报告链路。
- fixture、API mock、组件测试和截图必须分别标记。
- live 数据、真实模型、人工质量评测分别出证据。
- 缺少真实凭据时，状态写“未验证”或“blocked”，不得写“已支持”。

## 12. 数据接口策略

### 12.1 当前优先来源

- A 股与港股行情、财务三表：沿用当前受控 connector。
- A 股公告：巨潮资讯。
- 港股公告：HKEX 披露易。
- 用户研报：本地上传和解析。

### 12.2 可选开源适配器

- AKShare 可作为 A 股行情和财务数据适配器。
- Tushare、BaoStock 可作为备用数据服务，但需单独核验授权、配额、稳定性和再展示权限。
- SEC EDGAR、World Bank、ECB、FRED 等接口不属于本 MVP 的核心证据源。

免费接口不等于可商用或可再分发。任何新增接口都必须先登记来源权限、字段口径、速率限制、数据版本和失败降级方式。

## 13. 成功指标

北极星指标：

> 每周完成质证并下载报告的用户数。

健康指标：

- 报告下载率；
- 证据打开率；
- 重新研究率；
- 人工评测事实错误率；
- 单次任务成本；
- 端到端 P90；
- 失败和取消率。

---

## 14. 完成定义

只有同时满足以下条件，投研观点模块才可标记为 MVP 交付：

1. 三种输入方式全部通过真实链路验收；
2. 七块报告结构完整；
3. 研报能够作为证据并作为被质证对象；
4. 事实、推演、判断和证据边界清楚；
5. 50 条人工评测达到质量门槛；
6. 真实数据、真实模型和工程链路分别有证据；
7. 合规、隐私和来源边界通过检查；
8. 公共交付树干净，README、许可证和安全说明完整；
9. 用户完成最终签收。

任何 fixture、mock、截图或局部绿测都不能单独证明 MVP 已完成。
